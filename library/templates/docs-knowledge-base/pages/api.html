API reference

Three ways to talk to Beacon.

JSON over HTTPS, versioned, boring on purpose.

Base URL api.beacon.dev/v1. Authenticate with a bearer token from Settings, then API keys. Every list endpoint paginates with a cursor; every write returns the full object. Rate limit is 600 requests per minute per key, with the remaining count in a response header.

Make your first request
  • GET /monitors, POST /monitors, PATCH /monitors/:id
  • GET /incidents, POST /incidents/:id/acknowledge
  • GET /status-pages, POST /status-pages/:id/updates
  • POST /maintenance-windows for deploy automation
  • GET /uptime?monitor=:id&range=90d for reports

Signed POSTs when something changes.

Add a URL under Settings, then Webhooks, and Beacon sends a JSON payload on incident.opened, incident.updated, incident.resolved and monitor.paused. Each request carries an X-Beacon-Signature header: an HMAC-SHA256 of the body using your webhook secret. Failed deliveries retry with exponential backoff for 24 hours.

Webhook guide
  • Events: incident.opened, updated, resolved
  • Verify with HMAC-SHA256 and your secret
  • Idempotency key on every delivery
  • Replay any delivery from the dashboard
  • Test button sends a sample payload

The same API from your terminal.

Install with brew install beacon or npm install -g @beacon/cli. Run beacon login once; after that beacon monitors list, beacon incidents ack and beacon maintenance open are all one line. Output is a table by default or JSON with --json for scripts. The Beacon CLI is open source.

CLI guide
  • beacon monitors create --url https://example.com
  • beacon incidents list --open
  • beacon maintenance open --monitor web --minutes 15
  • beacon status post "Investigating elevated errors"
  • beacon uptime --range 30d --json
Core endpoints. All paths are relative to https://api.beacon.dev/v1 and require a bearer token.
Endpoint Method What it does Scope
/monitors GET, POST List monitors or create one; body matches the dashboard form read / write
/monitors/:id GET, PATCH, DELETE Read, update or remove a monitor; PATCH accepts partial objects read / write
/incidents GET Incidents with filters for state, monitor and date range read
/incidents/:id/acknowledge POST Stop escalation and record who acknowledged write
/maintenance-windows POST Open a window now or schedule one; pass monitor ids and minutes write
/status-pages/:id/updates POST Post an incident update to a status page and notify subscribers write
/uptime GET Uptime percentage and response-time percentiles for a range read
Versioning

v1 is stable. Fields are only ever added, never removed or renamed. Breaking changes would ship as v2 with at least twelve months of overlap.

New in October

POST /maintenance-windows now accepts a duration in minutes and returns the window id so your deploy script can close it early.

Rate limits

600 requests per minute per key. Exceeding it returns 429 with a Retry-After header. Polling /incidents every second is the usual cause; use webhooks instead.

Deprecated: legacy API keys

Keys created before March 2025 stop working on January 31, 2027. Create a scoped key under Settings, then API keys, and rotate it in. Email support@beacon.dev if you need help finding where the old one is used.
